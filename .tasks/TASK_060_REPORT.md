## Problems

**Seven places where a written prescription was wrong. Running count 104 → 111.**

1. **§0.1's premise.** The arity problem is a consequence of TASK_055 §2.8's
   *shape*, not of the bug class. The driver loop is pinned identical across
   rungs, so the slab must live inside the kernel; every rung is then
   `kernel(buf, off, len)` and the C gap is closed by **p14's existing
   `call_args` pin**. No dead argument, **no `harness/` change**. I measured the
   escape anyway as instructed.
2. **§2.8's "safe Rust is forced onto `(slot, generation)`" is false.** The
   handle comes out of a file, so it is an integer in every rung. Safe Rust is
   forced onto `Option<Box<u8>>`, which is niche-optimised to *the hardened-C
   representation*. The finding that replaces it is better: **the free and the
   invalidation are one operation in safe Rust and two in C, and the bug is the
   third — the asking — going missing.**
3. **The task's "this pattern will publish a smaller `tcb_items` than p01" is
   false.** p27 publishes **7** against p01's 3. §2.5's alarm is right in
   substance (the allocation adds **zero** project-local axioms) and wrong in its
   number, because a real pattern also indexes a table and reads a window.
4. **The catalogue's "singly linked list" shape is retracted** (class upheld).
   Priced in NOTES 0: where `next` sits decides observability and it is a glibc
   detail; and the bug would fire on *every* input, which B1 forbids.
5. **My own first draft asserted (in a comment) that `h < ntab <= TABCAP` deletes
   rustc's bounds check.** Three `panic_bounds_check` sites survive at `-O3`; the
   claim cost 41.62 Ir/call. Refuted by `r4_tabchecked`.
6. **A constraint nobody predicted: `vstd::raw_ptr::allocate`/`deallocate` carry
   no `#[inline]`**, so an R5 that calls them emits a GOT-indirect cross-crate
   call R4 cannot produce and the pair measures **`differ` at both opt levels**.
   **The minimal TCB and the `identity` pin are in tension** — you can have 5
   trusted items or a byte-identical pair, not both. Shipped: local
   `#[inline(always)]` copies whose *verified twins are vstd's own API*, so the
   gate proves they are no stronger.
7. **"The proof half is already settled — do not re-derive it" was not usable.**
   `a1_ghostloop.rs` splits **one** allocation `n` ways, which makes "free" a
   freelist push — the exact thing the task forbids. The proof was redone in a
   different shape (per-record `allocate`/`deallocate`,
   `Map<int,PointsTo<u8>>` + `Map<int,Dealloc>`, no split/join): **15 verified,
   0 errors, first run, functional postcondition included.**

Two gate-driven edits moved the contract hash from `b1f2dbb3…` to `a0e83e2f…`
(both recorded in NOTES with the reason): two `rec_alloc` `ensures` were **not
load-bearing**, and `rec_free`'s `Tracked(pt)` parameter pattern made six
`requires` conjuncts **unjudgeable** by the tautology probe. Both edits tighten
the gate; no `required`/`forbidden` entry moved.

Long runs used the harness's background mode (never `nohup &`), one at a time,
with nothing else running; completion was verified from the output file, not
assumed.
